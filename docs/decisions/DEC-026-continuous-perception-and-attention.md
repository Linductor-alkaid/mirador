## 背景与问题

[Issue #41 的维护者补充](https://github.com/Linductor-alkaid/mirador/issues/41#issuecomment-6258623068)
要求跨帧复用、OCR/Detector 实体整合、任务焦点、语义稳定化与选择性通知。已有
`PerceptionSession`、变化检测、能力缓存、`StableIdTracker`、`ObjectTracker`
分别提供所需原语，但当前没有统一的覆盖状态、延迟结果绑定和通知状态协议。
已有空间融合不能完整表示“同一实体的重复证据”“组件组成关系”“仅空间相交”。

[2026-10-20 的日期化后续](https://github.com/Linductor-alkaid/mirador/issues/41#issuecomment-6285521869)
在不改变任何既有诉求优先级的前提下，把维护方向固化为「增量视觉状态 + 事件驱动
理解 + 按需 VLM」的分层资源模型，并补充关系/事件契约字段、消失语义、源重置
事件终结、六条验收序列与职责边界收窄（第 8 节）。

## 决策

### 1. 连续表示状态持续，不表示库拥有循环或线程

暂定在 `mirador::fusion` 增加 Experimental 的 `ContinuousPerception` 协调对象，
组合已有会话/跟踪/缓存，不把这些组件在 Core 中重写。保持现有单帧入口默认行为。

提供同步 `plan / accept / query / drain_events` 形态的领域原语（名称在 M9-01
冻结）：调用方提交当前帧、策略和预算，库返回复用范围、需要识别的 ROI/优先级与
重新定焦建议；调用方执行 Backend，再将带绑定令牌的结果送入采纳点。可提供在
同一线程顺序完成这些步骤的便利入口，不引入 executor、future、后台回调或线程。
抓屏、输入频率、队列、并发与任务决策始终归 Mirage/Mira。

`ImageView/Frame` 继续非拥有。调用方执行跨帧任务时必须保持源图像存活直到任务结束；
库不为等待任务保留完整帧，只保存有界描述符、签名和结果。窗口/设备重建递增 source
epoch，不能用同名 source_id 让旧任务重新生效。

### 2. 在昂贵能力前应用声明式焦点

`AttentionPolicy` 暂定支持带坐标空间的 ROI、`stable_id + generation` 绑定，以及
对**已有可信观测**的文本/类别匹配；`ImportancePolicy` 提供显式优先级、识别预算与
通知过滤。二者为调用方配置，Mirador 不推断任务意义、不调用 LLM，也不把 importance
乘入 detection confidence。匹配条件有条数/字节上限，首版不用任意脚本或无界正则。

稳定 ID 焦点经当前跟踪位置映射到 ROI；过期 ID、代际或失去定位置信度时显式报告
`focus_unresolved`，不继续使用旧坐标。未见过的文本不能靠匹配器直接定位：首次使用
已有快照索引，否则由调用方预算授权 bootstrap 检测。无法解析焦点时不默默回到
昂贵的全屏识别。

焦点外继续低成本全局/外围分块变化检测。显著外围结构变化生成可查询的
`focus_reconsideration`/布局失效记录；是否通知及是否批准全量刷新取调用方策略。
预算不足时标记覆盖不完整，不能保持“未变化”保证。光标/动画过滤不成为永久盲区。

### 3. 复用必须证明覆盖，布局切换必须失效

不变区域可复用已验证的语义/行缓存；局部变化先做已有跟踪验证，再对受影响区域
增量识别；明显布局切换、旋转/分辨率/模型/策略范围变化使相关工作与覆盖失效，
请求调用方授权全量刷新。变化报告是失效线索，不是精确内容相等证明；小文字
变化场景用 DEC-023 精细模式及 ROI 精确摘要复核，不能只凭 dHash 相同复用文本。

每条结果保留 observed_frame、validated_frame、模型/参数身份、覆盖 ROI 与
freshness（新识别/验证复用/尚未验证/失效）。未执行、被 K 截断、被遮挡的区域为
unknown，不能当作实体消失或空文本。增量 ROI 的新结果只替换相同覆盖内、已完成
能力的旧证据；不能整幅删除焦点外实体。

### 4. 实体去重与从属关系分开表达

保留原始 OCR、Detector、外部区域证据及来源 ID，在现有融合输出旁增加有界关系
视图，首版不强行更换 `VisualRegion` 布局或改写旧融合默认值：

| 关系 | 规则与输出 |
| --- | --- |
| 同实体重复证据 | 几何、类别/文本兼容及可靠性均支持时合并，保留所有 evidence_ids 和 trace |
| 组件从属 | 按钮中的文字、容器中的图标建 `part_of` 边，父子仍可单独查询 |
| 普通相交 | 重叠但语义不兼容，保持独立；不能仅因包含关系做传递合并 |

图标被 OCR 误识别只形成冲突/低可靠候选；可结合检测类别、局部特征、跨帧验证
抑制其成为主文本，不销毁原证据、不宣称视觉推断是平台角色保证。关系图须拒绝环、
跨 epoch 引用和预算溢出，分裂/合并与新 ID 规则继续遵循 DEC-010。

### 5. 绑定延迟结果，输入积压在调用方有界处理

工作令牌至少绑定 source_id/epoch、frame_sequence、visual generation、
policy revision、请求/模型/实现身份、实际 ROI 与精确内容摘要。`accept` 先验证整批
几何和绑定，再原子提交；非法项按 DEC-021 整批拒绝。旧 epoch/策略、重复提交、
乱序或已失效内容产生显式 stale/rejected 原因与计数，不修改快照、跟踪或缓存。
首版不隐式把旧框平移到新帧；若允许未变 ROI 的延迟结果复用，必须在当前帧重新
验证精确内容与坐标后产生新的有效绑定。

参考调用方策略为每 source **一个在途工作 + 一个最新待处理帧**；新到帧替换等待
帧并报告 replaced_count，不能创建每帧一个任务的无界队列。库仅保留一个有界在途
工作描述符集合；跳帧不等于场景未变，重新处理时对比上一已处理/确认状态。取消、
超时和 stale 结果均不得推进 confirmed/published；允许独立记录失败诊断。

### 6. 最新观测、确认状态、通知状态各自演进

`TemporalSemanticState` 暂定分三层：latest observation、confirmed state、
last published state。对出现、消失、文字/外观/布局变化产生结构化差量；记录
observed/confirmed frame、stable ID、generation、变化种类、可靠性与证据来源。

暂定默认以 **2 次有效独立观测**确认出现/文字变化/消失，M9-06 校准；只有实际覆盖
并完成验证的观察才能推进计数，相同缓存快照重复查询不算第二次观察。消失要求
原区域有有效覆盖而目标缺失；未识别区域不推进消失。布局失效当次即可使旧动作
引用失效，不能等语义去抖结束才更新安全代际。

通知过滤只影响事件发布：忽略的可信变化仍更新内部确认状态与复用状态。视觉
generation 的失效规则不得被通知过滤阻止；event sequence 与 policy revision
独立于 generation。焦点切换时立即查询已有状态及其新鲜度，并对新策略生成有界
初始差量；缺乏新鲜证据时返回 unknown/待刷新，不能声称立即拥有未观察过的内容。

事件使用同步 pull/drain，不在库内发消息。事件队列按字节和条数封顶；允许合并
同实体重复变化，溢出计数与 `resync_required` 必须可见，调用方可查询当前完整状态
重建游标。不得丢事件后仍声称消费者已收到完整序列。

### 7. 所有新增状态有可核算预算

M9 暂定参考限制：额外协调状态 8 MiB、实体 1,024、关系 4,096、事件 256、焦点条件
64，每 source 一个在途描述符集合。字节核算包括文本、来源、关系、令牌和事件的
实际拥有容量；条数限制不替代字节预算。缓存继续沿用 DEC-008，跟踪池沿用既有
独立预算；报告各池上限与总拥有内存，禁止把同一对象漏算或共享所有权重复归属。
拒绝或显式淘汰均须有原因，不能静默只保留重要实体却宣称完整世界状态。

### 8. 关系/事件契约字段、消失语义与收窄的职责边界（2026-10-20 后续）

[Issue #41 的日期化后续](https://github.com/Linductor-alkaid/mirador/issues/41#issuecomment-6285521869)
不改变任何既有诉求优先级，为第 4/5/6 节补充如下评审方向；全部保持 Proposed。

**关系与事件的差分字段**：跨帧实体/几何关系的差分除第 6 节既有字段外，须携带
证据**来源**（产生该证据的观测）、同一稳定 ID 的**实例代际**（生命周期代）、
**证据时间窗**（观测与确认的时间上下文），以及事件的**开始/更新/结束**语义：
出现为 begin，文字/外观/关系变化为 update，确认消失为 end；同实体的持续存在
不产生重复事件。事件不依赖任何下游语义推理组件。

**消失语义**：遮挡、未分析、跟踪丢失不等同于确认消失——三者是可查询的中间
观测状态，只有第 6 节的有效覆盖缺失规则能推进 end。`TemporalSemanticState`
对失去定位的目标保留显式 occluded/tracking-lost 观测态，不把“跟踪器丢失”
发布为确认消失事件。**输入源重置（source epoch 递增）必须显式终结旧代未闭合
事件**（以 source reset 收尾而非 disappearance），禁止旧代证据在新代冒充新状态。

**分层资源模型**：Mirador 的高频低成本观测维护内部状态，变化驱动结构更新；
事件驱动的语义理解（VLM 等）是**下游可选升级**，其开关不影响状态层连续性
（M9 验收含“关闭语义升级仍连续”序列）。现有 fusion/`StableIdTracker`/
`ObjectTracker` 原语继续复用，本节不宣称能力缺失，只评审把它们组织为连续
关系/事件契约的最小公开接口（命名与形态由 M9-01 评审决定），下游不在应用层
复制跟踪/稳定化/差分算法。

**职责边界收窄**（全部归 Mirage/Mira）：产品事件日志的预算/保留与 gap 恢复、
任务重要性判定、VLM 升级去重、ROI/短窗模型请求、动作反馈关联、时间单元组织
与宿主消费。Mirador 不持有视频历史或常驻模型，只输出来源可追溯的增量与可查询
状态。**MiniCPM-o 4.5 仅作为视觉 token 压缩与时分复用组织的研究参考**：模型内
embedding 压缩依赖编码器/权重/下游 LLM 的联合兼容，压缩率不可换算为桌面链路
资源收益；Mirador 不引入该模型、权重、runtime 或模型序列协议，仍定位为通用
视觉状态与证据筛选组件。

## 备选方案

| 方案 | 取舍 |
| --- | --- |
| 完成全屏 OCR/YOLO 后才过滤通知 | 可降低上游噪声，但不能减少昂贵推理，不满足诉求 |
| 固定 ROI 且忽略外围 | 接入简单，滚动、弹窗与窗口切换会使焦点陈旧 |
| 在 Mirador 内建采集/任务循环/LLM 注意力 | 破坏视觉基础库与同步并发边界，不采用 |
| 所有包含区域直接合并 | 复用现有融合最便宜，但抹掉父子实体及独立可选目标 |
| 立刻扩写所有公共实体结构 | ABI 与语义风险大，先用 opt-in 关系视图和协调层验证 |

## 影响与风险

新增协调层是独立能力增量，不自动批准 DEC-022 的跟踪接口转正。真实桌面上的
去重、稳定化和外围监测可能互相牺牲召回；必须分别度量误合并、漏合并、通知漏报和
计算缩减，不能只以调用减少为成功。尚未提供真实数据的平台只保留构建级声明。

## 验证方式

[M9 验收矩阵](../plans/m9-continuous-perception.md)：伪 Backend 固定结果和帧序列
测试先行，再以同机全屏全量对照验证增量收益。必须包含 stale/乱序/积压、焦点
切换、外围弹窗、小文字变更、关系错误及事件溢出，不能只验证静态命中路径。
2026-10-20 后续补充六条序列：相似对象交换（稳定 ID 无证据不迁移）、遮挡后
重捕获、关系改变事件化、乱序/迟到结果不覆盖新状态、源重置旧代事件显式终结、
关闭语义升级时状态层仍连续（M9 AC9-11）。
