# DEC-011：基准设备清单与基准方法

> 状态：Accepted（2026-09-15，M5-01 冻结）
> 日期：2026-09-15
> 负责人：linductor
> 冻结里程碑：M5
> 替代/被替代：无

## 背景与问题

设计 §20 要求性能验收发布基准环境与数字（首版覆盖 Android ARM64 中端设备、x86_64
Linux 桌面与 Windows 桌面），总计划把 `DEC-011`（基准设备清单）的最迟冻结点定在
M5。本决策必须明确：

1. M5 评测与基准在哪些环境上执行；
2. 基准方法与统计口径（保证数字可复现、可比较）;
3. 暂不可得的环境如何处理（设计 §26 的性能验收不能因环境受限而虚化）。

## 决策

### 1. 基准环境清单

| 环境 | 角色 | 证据等级 | 说明 |
| --- | --- | --- | --- |
| Linux x64 工作站（Ubuntu 24.04，具体 CPU/内存/编译器版本随每次基准记录） | **主基准环境**：变化检测 p50/p95、缓存命中路径、Backend 外层耗时、RSS、模块体积 | 满足性能目标（固定方法、样本、硬件） | M5 性能数字的第一出处（`docs/benchmarks/`） |
| GitHub CI runner（ubuntu / windows / android NDK job） | 构建、测试与跨平台编译门禁 | 可以编译 / 可以运行 | runner 硬件不固定，**不得作为性能证据** |
| Android x86_64 模拟器（本机） | 功能与集成验证（采集示例、端到端流程） | 可以运行 | 绝对性能、功耗、温升不作结论 |
| 物理中端 Android 设备（ARM64） | 设计 §20 的 Android 基准（含功耗/温升趋势） | 暂缺 | 环境受限，补跑条件见下 |
| Windows x64 桌面 | Windows 基准 | 暂缺 | 同上（编译与测试门禁已由 CI 覆盖） |

补跑条件：获得物理中端 Android 设备与常驻 Windows 桌面后，由负责人按本决策方法
补跑对应基准并回填 `docs/benchmarks/`；在此之前，性能验收**明确限定**为 Linux x64
证据（工程规范 §7 与 `DOD-05`：未验证声明不得写成已验证），发布说明照此限定。

### 2. 基准方法（冻结口径）

- **输入**：确定性合成帧（无随机性），沿用 `benchmarks/change_detection_bench.cpp`
  的场景约定（不变画面、局部变化、旋转、动态区域忽略），并随 `M5-06` 扩展缓存命中
  与 Backend 外层耗时场景。
- **统计**：预热 + 固定迭代次数（现口径 20/300），报告 p50/p95 墙钟；每次基准记录
  OS、CPU、内存、编译器与构建类型四元组及 commit。
- **归因**：Core 外层开销与 Backend/runtime 内部耗时分开列报（`DEC-015` 第 4 节）；
  runtime 体积与 Core 体积分开列报（设计 §20）。
- **预算指标**：RSS 峰值、各模块静态/动态体积随基准一并报告。
- **复现**：基准入口随仓库提供（`benchmarks/`），结果文档必须含可复现命令。

## 备选方案

- 把「三平台中端代表设备」完整冻结为具体型号（如指定某款 ARM64 手机）：当前无可
  用设备，写成事实即违反工程规范 §7 证据等级；改为清单 + 补跑条件。被否（暂不可
  执行）。
- 用 CI runner 报告性能数字：硬件不固定，数字不可复现。被否。
- 推迟 `DEC-011` 到设备齐备：总计划已定最迟冻结点为 M5，且 Linux 主环境与方法
  口径不受设备可得性影响；先冻结可得部分并显式记录缺口。被否。

## 影响与风险

- M5 性能验收范围被限定为「Linux x64 完整 + Android/Windows 编译门禁」，跨平台
  性能结论待补跑——发布说明与 README 必须携带该限定。
- 模拟器功耗数据无意义，Android 功耗/温升指标整体挂起，不产生中间结论。
- 后续环境变化（更换工作站硬件）时，历史数字只对当时的四元组负责，跨环境比较
  需重跑。

## 验证方式

`M5-06` 按 §2 方法在主基准环境产出数字并登记 `docs/benchmarks/`；`M5-09` 收尾时
核对发布说明的限定表述与未完成补跑项。
