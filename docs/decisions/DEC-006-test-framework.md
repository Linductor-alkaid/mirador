# DEC-006：测试框架选型

> 冻结里程碑：M0

## 背景与问题

工作空间初始化阶段为保持零第三方依赖，smoke 测试暂以独立可执行文件 + CTest 实现。M0-08
需要确定统一测试框架，以支撑设计 §23 的单元/属性测试、测试标签与 Fake Backend 注入。
测试框架是首个进入构建的第三方依赖，须按工程规范 §9 锁定并登记许可证。

## 决策（暂定默认值）

采用 GoogleTest（pinned 版本待引入时确定，许可证 BSD-3-Clause）：

- 提供断言、夹具、值/类型参数化与死亡测试，覆盖坐标矩阵与 Fake Backend 注入需求。
- 社区成熟、CMake 集成（`FetchContent`/submodule）与 CI 支持广泛。
- 属性测试用自定义生成器 + GoogleTest 断言实现，暂不引入额外属性测试框架。

## 备选方案

- Catch2 v3：表达力好，静态库构建较重；可作为评审备选。
- doctest：编译最轻，但 mock/生态与团队既有经验弱。
- 维持自研最小断言库：长期维护成本高，放弃成熟标签与报告机制。

## 影响与风险

- 引入首个 `third_party/` 依赖：需 submodule + `dependencies.lock.json` 锁定，架构测试须
  确保其只链接进测试目标，不进入 `mirador-core` 链接闭包。
- 与 `DEC-002` 无 runtime 边界不冲突（仅测试使用）。

## 验证方式

`M0-08` 迁移 smoke 测试后，全部预设 build/test 通过；供应链文档登记许可证与锁定信息。
