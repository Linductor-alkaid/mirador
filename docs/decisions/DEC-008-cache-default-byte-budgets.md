# DEC-008：缓存默认字节预算

> 状态：Accepted（2026-09-14，M2 内冻结）
> 日期：2026-09-13（暂定默认值）；2026-09-14（冻结）
> 负责人：linductor
> 冻结里程碑：M2
> 替代/被替代：无

## 背景与问题

设计文档 §12/§20 要求所有缓存有字节上限（`RULE-06`），但未规定默认值。总计划自 M1 起
记录暂定默认值"帧 4 MiB、能力结果 16 MiB（参照设计 §25 示例）"，最迟须在 M2 冻结，否则
`PerceptionSession` 的配置默认值没有可引用的依据。M1 的 `FrameCache` 已要求调用方显式
传入预算（`create(max_bytes)`），缺省值只应存在于会话配置层，而不应藏在缓存类型内部。

## 决策

1. 默认预算在 `PerceptionSessionOptions` 中定义：`frame_cache_bytes = 4 MiB`、
   `result_cache_bytes = 16 MiB`，与设计 §25 示例一致。
2. 缓存类型本身（`FrameCache`、`CapabilityResultCache`）不携带默认预算：`create` 必须
   显式接收 `max_bytes`，非正值返回 `kInvalidArgument`。缺省值属于策略层（会话配置），
   不属于机制层（缓存容器）。
3. 帧级 4 MiB 覆盖"缩略图、指纹与变化检测中间量"；能力结果 16 MiB 覆盖"OCR 文本框与
   检测框等小型结构化结果"（设计 §12：完整截图与小型结构化结果不互相挤占，默认不长期
   缓存完整屏幕）。会话内部的跨帧 `ChangeSignature` 不经帧缓存，作为固定小对象直接持有
   （64×64 灰度缩略图 ≤ 4 KiB + 64 位指纹）。
4. 两个默认值只约束 Mirador 自带的会话配置；调用方显式传入 0/负值时按 `kInvalidArgument`
   拒绝，不回退默认值，避免"看似自定义实则缺省"的歧义。

## 备选方案

- 缓存类型内建默认预算：机制层隐含策略，调用方难以审计内存占用，被否。
- 更大的默认值（如能力结果 64 MiB）：无实测需求支撑，违背"避免工作、低负载"定位；超出
  部分由调用方显式上调即可，被否。
- 不设默认、强制调用方全部显式：与设计 §25 示例的可用性目标冲突，且暂定值已在 M1 验证
  路径上使用，被否。

## 影响与风险

- 多源场景内存占用 ≈ 每源 20 MiB + 签名/帧状态；调用方可按设备档次显式缩放。
- 若 M5 基准证明默认值在低端 Android 设备上偏高或偏低，须修订本决策并同步会话默认值、
  文档与测试，不得静默更改。

## 验证方式

`M2-04`/`M2-05`：会话默认构造使用上述值的断言；预算 0/负值显式报错的负向测试；缓存
预算与淘汰路径测试（`M2-02`）。见 `tests/fusion/perception_session_test.cpp`、
`tests/cache/capability_cache_test.cpp`。
